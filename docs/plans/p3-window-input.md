# P3 extended input execution slice

Continues the approved product roadmap P3.3 in the existing viewer/agent architecture. Apple Silicon is the product host; Linux cloud verifies portable logic and Windows CI verifies USER32 fixtures. This is not full Coherence or video acceptance.

Protocol v10 adds bounded, incarnation-checked pointer clicks (primary/secondary, single/double observed click ordinals), wheel, bounded drag, keyboard chords and client resize. Old protocols reject new actions before mutation. Click count1 sends down/up; count2 sends only double-click/up after the first click, avoiding three clicks. Pointer messages are addressed to the selected root's child; no host/global pointer injection. Drag uses at most16 interpolated moves and always attempts button release after a failed post. Resize changes client size, preserves position/z-order and stays within64–8192 pixels. Keyboard shortcuts require the selected root to already be foreground, no physical modifiers/keys held, then send one bounded down/up batch; no focus bypass, automatic retry or input replay. Native destruction/foreground changes remain operation-time races, not atomic guarantees.

Viewer negotiates window_input v10 once at open, keeps basic input for older agents, maps Mac Command to guest Control and offers explicit client-size controls. Only a focused image accepts keys/drag; hovering accepts wheel. Image coordinates stay normalized to current frame. Queue remains bounded32; switching target drops pending input. No live video or performance claim.

Validation: protocol accepted/bad bounds and legacy refusal RED→GREEN; host response/version mismatch and wrong-target refusal; owned Windows windows inspect actual posted messages, resize and stale-target refusal. Native shortcut acceptance is separately gated on Windows desktop availability and must not be represented as Mac acceptance. Full workspace lint/tests, Windows ARM build, native CI, actual EN/VI viewer capture, single fresh whole-batch review, then immutable release.

# Application compatibility evidence

The target is broad Windows application support on Apple Silicon. A finite test suite cannot establish that every Windows executable works. Record architecture, Windows build, driver requirements and actual operation for every tested application. Starting a process is weaker evidence than observing its intended behavior; a PID alone is not success.

External test applications remain local test inputs, not bundled into this repository or a product. Preserve their license notices and source/digest provenance. For 7-Zip, official artifacts came from https://github.com/ip7z/7zip/releases/tag/25.01. No application runtime success is inferred from a successful download or checksum.

For repeatable archive acceptance, place `scripts/windows-archive-smoke.cmd` on a readonly tools CD alongside the verified official `7zip-extra` directory and test input `serial/vioser.inf`. Run it in the installed interactive Windows session with a new output directory, for example `E:\windows-archive-smoke.cmd C:\FreeLaneTest\run-1`. It refuses an existing directory, saves `result.txt`, and checks create/test/extract plus `fc /b` for x86, x64 and ARM64, stopping on failure. Acceptance requires the observed final `AcceptanceExitCode=0` and a complete transcript; an interrupted run or missing result proves nothing. After a clean reboot, separately compare the saved files again to establish persistence. The script is a prepared diagnostic; its availability is not evidence that all checks passed.

Installed-desktop acceptance should include file creation, open/edit/save/reopen, application restart and guest reboot persistence. Windows ARM translation, storage, networking, display and input must be exercised separately. Benchmark only verified workloads on the same real Mac used for the comparison; software ARM emulation in Linux supplies correctness experiments rather than Parallels performance evidence.

The installed Audit guest recorded bugcheck `0x139` with first parameter `3` during the byte-comparison attempt. An offline ARM64 helper using Windows' own DbgEng read the dump and found `nt` and `WdFilter` stack frames; this identifies participating modules, not the root cause. A single-threaded TCG diagnostic option is now available, but a passing UEFI smoke test does not establish Windows stability. Native `Confirm-SecureBootUEFI` returned `True`; `Get-Tpm` failed with `0x80284001`, so installed-guest TPM readiness is not verified. Host log inspection cannot read the BitLocker Windows volume; use guest-native diagnostics without exporting keys.

The later single-threaded installed Audit trial completed the scripted archive checks for x86, x64 and ARM64, with all three explicit PASS markers and byte comparisons in the native log. Its final numeric batch exit status was not captured; that limits this recorded trial even though each workload's PASS marker and the final success line were observed. This is one input file and one trial, not proof of a crash fix or universal app compatibility. Software-emulated startup and process launches were very slow; native Mac measurements are still required. See [recorded test evidence](test-evidence.md).
